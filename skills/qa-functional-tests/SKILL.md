Orchestrates functional test generation and automatic quality review with intelligent parallelization:
- **Small stories (1-5 ACs)**: Single agent with plan mode (5-10 minutes)
- **Large stories (6+ ACs)**: Multiple parallel specialists (8-12 minutes, 70-80% faster)
- **Large test files (>35 tests)**: Chunked parallel review

## Output Directory

**IMPORTANT**: All QA artifacts are stored in the **PROJECT directory**, not the global ~/.claude/ directory.

All test documentation generated by this command should be saved to:
```
.claude/qa/<YYYYMMDD>-<feature-slug>/functional-tests.md
```

Example: `.claude/qa/20251204-order-execution-flow/functional-tests.md`

## Your Task

Orchestrate functional test generation and automatic quality review for the feature described by the user. This command:
1. Detects story size (acceptance criteria count)
2. **Small stories (≤5 ACs)**: Spawns single qa-functional-engineer with plan mode
3. **Large stories (>5 ACs)**: Spawns multiple qa-functional-engineer specialists IN PARALLEL (no coordinator)
4. Combines results (for large stories)
5. Reviews tests:
   - **Small files (≤35 tests)**: Single reviewer with plan mode
   - **Large files (>35 tests)**: Multiple parallel chunk reviewers
6. Combines review results (for large files)
7. Displays combined summary

**Key improvements (2026-01-16)**:
- Eliminated coordinator pattern (simpler, more reliable)
- Direct parallel spawning of specialists (no ExitPlanMode complexity)
- Chunked review for large test files (handles context limits)
- 70-80% performance improvement for large stories

### Step 1: Parse User Story and Create Output Directory

Analyze the provided feature description and create output directory:

```bash
# Extract feature description from user input
FEATURE="$ARGUMENTS"

# Create feature slug for directory name
FEATURE_SLUG=$(echo "$FEATURE" | tr '[:upper:]' '[:lower:]' | tr ' ' '-' | sed 's/[^a-z0-9-]//g' | cut -c1-50)

# Create output directory with date prefix
DATE=$(date +%Y%m%d)
OUTPUT_DIR=".claude/qa/${DATE}-${FEATURE_SLUG}"
mkdir -p "$OUTPUT_DIR"

echo "Output directory created: $OUTPUT_DIR"
```

Extract key information from feature description:
- Count acceptance criteria sections (if present)
- Identify interfaces involved (UI, REST, FIX, WebSocket)
- Note complexity level (number of ACs, business rules, integrations)

### Step 1.5: Detect Acceptance Criteria Count and Choose Generation Mode

Analyze the user story to determine batch vs direct generation.

**AC Format**: User stories have "Acceptance Criteria:" header followed by numbered list (1., 2., 3.)

Use **Grep tool** to detect AC count:

```bash
# Find the "Acceptance Criteria:" section and count numbered items
AC_SECTION_START=$(echo "$FEATURE" | grep -n "^Acceptance Criteria:" | cut -d: -f1 | head -1)

if [ -z "$AC_SECTION_START" ]; then
    # No "Acceptance Criteria:" header found - ask user
    # Use AskUserQuestion tool with single question
    # Question: "How many acceptance criteria does this user story have?"
    # Options: "1-2", "3-5", "6-9", "10+"
    # Store numeric answer in AC_COUNT variable
    echo "⚠️ Could not detect 'Acceptance Criteria:' header"
else
    # Extract AC section and count numbered items (lines starting with digit + period)
    AC_SECTION=$(echo "$FEATURE" | tail -n +$AC_SECTION_START)
    AC_COUNT=$(echo "$AC_SECTION" | grep -c "^[0-9]\+\." || echo "0")

    echo "Story has $AC_COUNT acceptance criteria (detected from numbered list)"
fi

# Determine generation mode based on AC count
if [ "$AC_COUNT" -gt 5 ]; then
    echo "✅ Large story detected: $AC_COUNT acceptance criteria"
    echo "   Using parallel generation mode for optimal performance"
    echo "   Each specialist will generate ~20-30 tests in 3-5 minutes"
    USE_BATCHING=true

    # Extract and split acceptance criteria for parallel processing
    echo "   Extracting and splitting acceptance criteria into batches..."

    # Extract the Acceptance Criteria section (from header until next major section)
    AC_SECTION=$(echo "$FEATURE" | sed -n '/^Acceptance Criteria:/,/^[A-Z][a-z]* [A-Z]/p' | sed '$d')

    # If extraction failed, try alternative approach (until end of file or double newline)
    if [ -z "$AC_SECTION" ]; then
        AC_SECTION=$(echo "$FEATURE" | sed -n '/^Acceptance Criteria:/,$p')
    fi

    # Calculate number of batches (3 ACs per batch for optimal specialist workload)
    BATCH_SIZE=3
    NUM_BATCHES=$(( (AC_COUNT + BATCH_SIZE - 1) / BATCH_SIZE ))

    echo "   Will spawn $NUM_BATCHES specialist agents in parallel"

    # Extract ACs for each batch
    declare -a BATCH_ACS
    declare -a BATCH_RANGE

    for i in $(seq 1 $NUM_BATCHES); do
        START_AC=$(( (i - 1) * BATCH_SIZE + 1 ))
        END_AC=$(( i * BATCH_SIZE ))
        [ $END_AC -gt $AC_COUNT ] && END_AC=$AC_COUNT

        # Extract specific ACs for this batch using awk
        BATCH_ACS[$i]=$(echo "$AC_SECTION" | awk -v start=$START_AC -v end=$END_AC '
            /^[0-9]+\./ {
                ac_num = substr($1, 1, length($1)-1)
                if (ac_num >= start && ac_num <= end) print_flag = 1
                else if (ac_num > end) print_flag = 0
            }
            print_flag { print }
        ')

        BATCH_RANGE[$i]="$START_AC-$END_AC"
        echo "   Batch $i: ACs $START_AC-$END_AC"
    done
else
    echo "✅ Standard story: $AC_COUNT acceptance criteria"
    echo "   Using direct generation mode with plan approval"
    USE_BATCHING=false
fi
```

**Generation Mode Decision**:
- **6+ ACs**: Batch generation (prevents long waits, shows progress)
- **1-5 ACs**: Direct generation (fast enough, keeps plan mode QA)

**Step 2.5: Combine Results (Large Stories Only)**

After all specialist agents complete (Task tools return), combine their output into a single file:

```bash
if [ "$USE_BATCHING" = true ]; then
```

**Step 4.5: Combine Review Results (Large Files Only)**

After all chunk review agents complete, combine their results into a single review file:

```bash
if [ "$TOTAL_TESTS" -gt "$CHUNK_SIZE" ]; then
    echo ""
    echo "📋 Combining review results from $NUM_CHUNKS chunks..."

    # Create combined review with overall summary
    cat > "${OUTPUT_DIR}/functional-tests-review.md" <<EOF
---
feature: "${FEATURE_NAME}"
total_chunks: ${NUM_CHUNKS}
total_tests: ${TOTAL_TESTS}
reviewed: $(date -u +"%Y-%m-%dT%H:%M:%SZ")
---

# Functional Test Review: ${FEATURE_NAME}

## Overall Summary

Total test cases reviewed: ${TOTAL_TESTS} (across ${NUM_CHUNKS} chunks)

EOF

    # Append each chunk review
    for chunk_num in $(seq 1 $NUM_CHUNKS); do
        CHUNK_REVIEW="${OUTPUT_DIR}/review-chunk-${chunk_num}.md"

        if [ -f "$CHUNK_REVIEW" ]; then
            echo "## Chunk $chunk_num Review" >> "${OUTPUT_DIR}/functional-tests-review.md"
            echo "" >> "${OUTPUT_DIR}/functional-tests-review.md"

            # Strip frontmatter and append content
            sed '1,/^---$/d; 1,/^---$/d' "$CHUNK_REVIEW" >> "${OUTPUT_DIR}/functional-tests-review.md"
            echo "" >> "${OUTPUT_DIR}/functional-tests-review.md"
        else
            echo "❌ Warning: Chunk review $chunk_num not found at $CHUNK_REVIEW"
        fi
    done

    # Calculate overall quality metrics (from chunk reviews)
    # Extract quality scores from each chunk
    QUALITY_SCORES=""
    for chunk_num in $(seq 1 $NUM_CHUNKS); do
        CHUNK_REVIEW="${OUTPUT_DIR}/review-chunk-${chunk_num}.md"
        if [ -f "$CHUNK_REVIEW" ]; then
            SCORE=$(grep "^quality_score:" "$CHUNK_REVIEW" | head -1 | cut -d':' -f2 | tr -d ' ' || echo "0")
            QUALITY_SCORES="$QUALITY_SCORES $SCORE"
        fi
    done

    # Calculate average quality score
    if [ -n "$QUALITY_SCORES" ]; then
        AVG_SCORE=$(echo "$QUALITY_SCORES" | awk '{sum=0; n=0; for(i=1;i<=NF;i++){sum+=$i; n++}} END{if(n>0) printf "%.1f", sum/n; else print "N/A"}')
        echo "" >> "${OUTPUT_DIR}/functional-tests-review.md"
        echo "## Overall Quality Metrics" >> "${OUTPUT_DIR}/functional-tests-review.md"
        echo "" >> "${OUTPUT_DIR}/functional-tests-review.md"
        echo "Average quality score across all chunks: $AVG_SCORE/10" >> "${OUTPUT_DIR}/functional-tests-review.md"
    fi

    # Clean up chunk files and individual reviews
    rm -f "${OUTPUT_DIR}"/chunk-*.md "${OUTPUT_DIR}"/review-chunk-*.md

    echo "✅ Combined review from $NUM_CHUNKS chunks"
    echo "🧹 Cleaned up temporary chunk files"
    echo ""
fi
```

## Important Notes

**Execution Model**:
- **Small stories (≤5 ACs)**: Single agent with plan mode (user approves plan before execution)
- **Large stories (>5 ACs)**: Multiple specialists spawned IN PARALLEL (single message, multiple Task calls)
  - NO plan mode for specialists (direct generation for speed)
  - Each specialist writes to separate part file
  - Orchestrator combines results after all specialists complete
- **Small review files (≤35 tests)**: Single reviewer with plan mode (user approves plan)
- **Large review files (>35 tests)**: Multiple chunk reviewers IN PARALLEL
  - Each reviewer handles a chunk of ~35 tests
  - Orchestrator combines review results

**Plan Mode Behavior**:
- Small stories: qa-functional-engineer uses plan mode (user approves)
- Large stories: Specialists skip plan mode (direct generation)
- Small review files: qa-test-plan-reviewer uses plan mode (user approves)
- Large review files: Chunk reviewers skip plan mode (direct review)

**Parallel Execution**:
- For large stories: ALL specialists spawned in SINGLE message with MULTIPLE Task calls
- For large review files: ALL chunk reviewers spawned in SINGLE message with MULTIPLE Task calls
- Follows CLAUDE.md parallel execution mandate
- No coordinator agent (simplified approach, more reliable)

**User Approval Points**:
- Small stories: Approve test generation plan (from qa-functional-engineer)
- Small review files: Approve review plan (from qa-test-plan-reviewer)
- Large stories: NO approval needed (specialists run directly)
- Large review files: NO approval needed (chunk reviewers run directly)

**Output Files**:
- Tests: `functional-tests.md` (combined from all sources)
- Review: `functional-tests-review.md` (combined from all chunks if applicable)
- Temporary files cleaned up automatically

## Troubleshooting

**If you see an agent asking for plan approval**:
- This is NORMAL for small stories (≤5 ACs) and small review files (≤35 tests)
- DO NOT try to answer it yourself
- The USER will respond to the agent directly
- Just wait for the Task tool to complete
- Large stories use specialists WITHOUT plan mode (no approval needed)

**If tests not generated for large stories**:
- Check for specialist output files: `functional-tests-part-*.md`
- Verify all specialists completed successfully
- Check if combination step succeeded
- Look for error messages in specialist agent outputs
- If some parts missing: partial results may still be useful

**If review not generated**:
- For small files: Check `${OUTPUT_DIR}/review-plan.md` for plan
- For large files: Check for chunk review files: `review-chunk-*.md`
- Verify reviewer agents completed successfully
- Tests are still valid without review (review is enhancement)

**If parallel spawning fails**:
- Verify all specialists were spawned in SINGLE message with MULTIPLE Task calls
- Check for connection/rate limit errors
- If needed, fall back to small story approach (set AC_COUNT to 5 manually)

**Performance issues**:
- Large stories should complete in 8-12 minutes
- If taking longer: check if specialists are actually running in parallel
- Monitor system resources (memory, CPU)
- Consider adjusting BATCH_SIZE or CHUNK_SIZE if needed

## Output Directory

**IMPORTANT**: All QA artifacts are stored in the **PROJECT directory**, not the global ~/.claude/ directory.

All test documentation generated by this command should be saved to:
```
.claude/qa/<YYYYMMDD>-<feature-slug>/chaos-tests.md
```

Example: `.claude/qa/20251204-order-execution-flow/chaos-tests.md`

## Your Task

Generate comprehensive chaos engineering and resilience test scenarios covering failover, recovery, network partitions, service degradation, data loss prevention, and system resilience for the feature described by the user.

## Test Types Argument

This command defaults to `--test-types=chaos` but can be overridden to include additional test types:

**Default:** `--test-types=chaos`
**Override examples:**
- `--test-types=chaos,functional` (add functional tests)
- `--test-types=all` (generate all test types)

## Input

The user will provide:
- Feature description or user story
- Specific resilience concerns (if any)
- System components involved (if specified)
- **Optional**: `--test-types` argument (defaults to `chaos`)

## Required Process

1. **Analyze Resilience Requirements**
   - Identify critical failure scenarios
   - Determine RTO (Recovery Time Objective) and RPO (Recovery Point Objective)
   - Assess zero-loss guarantees
   - Identify cluster components (Leader/Followers)

2. **Create Output Directory**
   Create the project QA artifacts directory:
   ```bash
   FEATURE_SLUG=$(echo "$ARGUMENTS" | tr '[:upper:]' '[:lower:]' | tr ' ' '-' | sed 's/[^a-z0-9-]//g')
   OUTPUT_DIR=.claude/qa/$(date +%Y%m%d)-${FEATURE_SLUG}
   mkdir -p ${OUTPUT_DIR}
   ```

3. **Invoke the QA Principal Engineer Agent (Coordinator) - Plan Mode**

   **IMPORTANT**: The qa-principal-engineer will FIRST enter plan mode to create an execution plan.

   Use the Task tool to invoke the qa-principal-engineer agent:

   ```
   Analyze the following feature and create a comprehensive test generation plan:

   Feature: [Feature description]
   Test Types Requested: chaos (or from --test-types argument if provided)

   Requirements:
   1. Enter plan mode FIRST
   2. Parse test-types argument: chaos (default) or user-provided value
   3. Determine which agents to spawn (qa-chaos-engineer, and others if test-types includes them)
   4. Define scope for chaos testing:
      - Failover testing (cluster leader failure, follower promotion)
      - Recovery testing (snapshot recovery, event replay, RTO measurement)
      - Network partition testing (split-brain prevention, cluster consensus)
      - Service failure simulation (OMS crash, Matching Engine failure, LP timeout)
      - Data loss prevention (zero transaction loss validation)
      - State consistency under failure (deterministic replay validation)
      - Cascading failure prevention (circuit breakers, bulkheads, timeouts)
      - Disaster recovery (datacenter failure, backup restore)
      - Back-pressure testing (overload handling, graceful degradation)
      - Chaos experiments (controlled failure injection, Chaos Monkey patterns)
   5. Write execution plan to ~/.claude/plans/qa-execution-plan.md
   6. Exit plan mode for user approval
   7. After approval, spawn qa-chaos-engineer agent (and others if requested) with isolated context

   COVERAGE REQUIREMENTS:
   - Generate comprehensive chaos engineering test coverage
   - No limits on test case count (generate ALL necessary scenarios)
   - Follow TEST_CASE_BEST_PRACTICES.yaml methodology
   - Include latency spike and recovery time measurements
   - Validate zero transaction loss (event sourcing durability)
   - Reference specific codebase components (Aeron Cluster, event sourcing)

   OUTPUT DESTINATION:
   - Chaos tests: ${OUTPUT_DIR}/chaos-tests.md
   ```

   Save the complete chaos engineering scenarios to: ${OUTPUT_DIR}/chaos-tests.md
   ```

4. **Invoke the QA Test Plan Reviewer Agent**
   Use the Task tool to invoke the qa-test-plan-reviewer agent:

   ```
   Review the chaos engineering scenarios created by the qa-chaos-engineer agent.

   Evaluate across these critical dimensions:
   - Failure Scenario Coverage (cluster, service, network, resource failures)
   - Resilience Validation (failover speed, recovery correctness, zero loss)
   - Hypothesis Quality (clear expected behavior, testable predictions)
   - Observability Requirements (adequate metrics, logs for validation)
   - Blast Radius Management (safe failure injection, rollback procedures)
   - Strategic Gaps (missing failure modes, untested recovery paths)

   Provide:
   - Executive Summary with overall quality score (1-10) and critical blockers
   - Detailed Findings for each dimension with specific gaps
   - Missing Chaos Scenarios
   - High-Risk Failures not adequately tested
   - Quality Gate verdict: APPROVED / APPROVED WITH CONCERNS / BLOCKED

   Read the chaos scenarios file at ${OUTPUT_DIR}/chaos-tests.md and provide specific, actionable feedback.

   Save your review to: ${OUTPUT_DIR}/chaos-tests-review.md
   ```

5. **Address Reviewer Findings**
   If the reviewer identifies issues (APPROVED WITH CONCERNS or BLOCKED):

   Use the Task tool to invoke the qa-chaos-engineer agent again:

   ```
   Address the following issues identified by the qa-test-plan-reviewer:

   [List of specific issues from reviewer]

   Update the chaos scenarios to:
   - Add missing failure scenario types
   - Enhance failure injection procedures
   - Address all CRITICAL and HIGH severity findings
   - Add missing recovery validation steps
   - Improve observability requirements
   - Add missing blast radius mitigations

   Update the chaos scenarios file at ${OUTPUT_DIR}/chaos-tests.md with the improvements.
   ```

6. **Final Review (if needed)**
   If significant changes were made, optionally invoke the reviewer again to validate improvements.

7. **Present Final Output**
   - Present the reviewed and improved chaos scenarios
   - Display the file location: `${OUTPUT_DIR}/chaos-tests.md`
   - Display the review location: `${OUTPUT_DIR}/chaos-tests-review.md`
   - Highlight the review verdict and quality score
   - Note critical failure scenarios that received special attention
   - Call out RTO/RPO targets and zero-loss guarantees
   - Suggest chaos engineering tools (Chaos Monkey, Gremlin, Toxiproxy)
   - Highlight areas needing continuous resilience testing

## Example Usage

User: "Generate chaos engineering test scenarios for the new Aeron Cluster consensus layer"

Agent: [Invokes qa-chaos-engineer agent to generate leader failure scenarios, follower failover tests, network partition simulations, snapshot recovery validation, and deterministic replay tests]
